Fördjupad OOP i C# · Kurs 3 · CLO26 · YRGO

Välj databas

EF Core fungerar med flera databaser. Varje avsnitt nedan har sina egna paket, sin connection string och sitt eget sätt att köra databasen. Välj det du ska använda.

DatabasNär du använder denHur den körs
SQLiteSnabbast att komma igång med. En fil på disken, ingen server.Ingen installation
SQL ServerOm du kör Windows och Visual Studio.LocalDB (Windows) eller Docker
MySQLOm du vill jobba med MySQL, till exempel i kurs 2.Docker

Har du Windows och Visual Studio: använd LocalDB under SQL Server. Annars: använd Docker.

Skapa projektet

Skapa ett konsolprojekt. Det gör du en gång, oavsett databas:

dotnet new console -n EfLathund
cd EfLathund

Installera dotnet-ef en gång på datorn. Det är verktyget som kör migrationer:

dotnet tool install --global dotnet-ef

Kontrollera att det fungerar:

dotnet ef --version

Kör först konfigurationspaketen:

dotnet add package Microsoft.Extensions.Configuration.Json
dotnet add package Microsoft.Extensions.Configuration.UserSecrets

dotnet add package Microsoft.EntityFrameworkCore.Design

{

  }
}

Kör

Ingen server behövs. Filen webshop.db skapas i projektmappen när du kör migrationerna.

OnConfiguring

optionsBuilder.UseSqlite(config.GetConnectionString("Sqlite"));

Paket

Kör först konfigurationspaketen:

dotnet add package Microsoft.Extensions.Configuration.Json
dotnet add package Microsoft.Extensions.Configuration.UserSecrets
dotnet add package Microsoft.Extensions.Configuration.EnvironmentVariables

Sedan Design och SQL Server-providern:

Connection string

Lägg till i appsettings.json. Lösenordet hör inte hemma i filen, se avsnittet Hemligheter:

{
  "ConnectionStrings": {
    "SqlServer": "Server=localhost,1433;Database=Webshop;User Id=sa;Password=<lösenord>;TrustServerCertificate=True",
    "LocalDb": "Server=(localdb)\\MSSQLLocalDB;Database=Webshop;Trusted_Connection=True;TrustServerCertificate=True"
  }
}

Kör: Windows och Visual Studio (LocalDB)

LocalDB följer med Visual Studio. Ingen installation behövs. Använd connection string LocalDb.

Kör: Docker

docker run -e "ACCEPT_EULA=Y" -e "MSSQL_SA_PASSWORD=<starkt lösenord>" -p 1433:1433 --name sql1 -d mcr.microsoft.com/mssql/server:2022-latest

Lösenordet måste vara minst 8 tecken och innehålla stora och små bokstäver, siffror och ett specialtecken. Det är samma lösenord som i connection string.

Kontrollera att containern kör:

docker ps

Starta en stoppad container med docker start sql1.

OnConfiguring

optionsBuilder.UseSqlServer(config.GetConnectionString("SqlServer"));
// eller, med LocalDB:
// optionsBuilder.UseSqlServer(config.GetConnectionString("LocalDb"));

    "MySql": "Server=localhost;Port=3306;Database=webshop;User=root;Password=<lösenord>"

Kontrollera att containern kör med docker ps. Starta en stoppad container med docker start mysql1.

optionsBuilder.UseMySql(config.GetConnectionString("MySql"), ServerVersion.AutoDetect(config.GetConnectionString("MySql")));
Hemligheter

Lösenord ska inte ligga i appsettings.json, eftersom filen kan hamna i git. Gäller för alla databaser.

User secrets

Sparas utanför projektmappen, så de hamnar inte i git. Exemplet gäller SQL Server. Byt nyckelnamn för din databas:

dotnet user-secrets init
dotnet user-secrets set "ConnectionStrings:SqlServer" "Server=localhost,1433;Database=Webshop;User Id=sa;Password=<ditt riktiga lösenord>;TrustServerCertificate=True"

Miljövariabler

Två understreck (__) betyder ett nivåsteg i JSON:

# PowerShell
$env:ConnectionStrings__SqlServer = "Server=localhost,1433;Database=Webshop;User Id=sa;Password=<lösenord>;TrustServerCertificate=True"

# bash
export ConnectionStrings__SqlServer="Server=localhost,1433;Database=Webshop;User Id=sa;Password=<lösenord>;TrustServerCertificate=True"

Kopiera appsettings.json till output: sätt Copy to Output Directory till Copy if newer.

DbContext och modell

En modell är en vanlig C#-klass. DbContext är klassen som pratar med databasen. DbSet<T> är en tabell. Välj den rad i OnConfiguring som matchar din databas från avsnittet ovan.

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public decimal Price { get; set; }
}

public class WebshopContext : DbContext
{
    public DbSet<Product> Products => Set<Product>();

    protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
    {
        var config = new ConfigurationBuilder()
            .AddJsonFile("appsettings.json")
            .AddUserSecrets<WebshopContext>(optional: true)
            .AddEnvironmentVariables()
            .Build();

        // Välj EN rad, beroende på din databas:
        optionsBuilder.UseSqlite(config.GetConnectionString("Sqlite"));
        // optionsBuilder.UseSqlServer(config.GetConnectionString("SqlServer"));
        // optionsBuilder.UseMySql(config.GetConnectionString("MySql"), ServerVersion.AutoDetect(config.GetConnectionString("MySql")));
    }
}

Konstruktorn är tom, och det är med avsikt. Migrationsverktyget (dotnet ef) behöver kunna skapa kontexten utan argument. Därför läser vi konfigurationen i OnConfiguring.

CRUD

Alla operationer följer samma mönster: ändra objekt i minnet, och anropa SaveChanges() för att skriva till databasen.

Create

Lägg till en rad. Ingenting sparas förrän du anropar SaveChanges().

using var db = new WebshopContext();

db.Products.Add(new Product { Name = "Kaffe", Price = 49m });
db.SaveChanges();

Read

Hämta med LINQ. Find söker på primärnyckel. Where och ToList hämtar en lista.

using var db = new WebshopContext();

var produkt = db.Products.Find(1);
var billiga = db.Products
    .Where(p => p.Price < 100)
    .ToList();

Update

Hämta objektet, ändra egenskapen och spara. EF håller koll på vad som ändrats.

using var db = new WebshopContext();

var kaffe = db.Products.First(p => p.Name == "Kaffe");
kaffe.Price = 39m;
db.SaveChanges();

Delete

Ta bort objektet och spara.

using var db = new WebshopContext();

var kaffe = db.Products.First(p => p.Name == "Kaffe");
db.Products.Remove(kaffe);
db.SaveChanges();

Glöm inte SaveChanges(). Utan det händer ingenting i databasen, och programmet ger ingen felsignal.

Transaktioner

SaveChanges() körs redan i en transaktion, så alla ändringar i ett anrop lyckas eller misslyckas tillsammans. Vill du styra flera anrop själv använder du en egen transaktion:

using var db = new WebshopContext();
using var transaction = db.Database.BeginTransaction();
try
{
    db.Products.First(p => p.Name == "Kaffe").Price -= 5;
    db.Orders.Add(new Order { ProductId = 1 });
    db.SaveChanges();
    transaction.Commit();
}
catch
{
    transaction.Rollback();
    throw;
}

Samma idé som i ADO.NET-lathunden. Skillnaden är att EF Core skriver SQL:en åt dig.

Migrationer

En migration är en fil som beskriver en ändring i databasens struktur. Den ändrar tabeller, inte data. Så här skapar och kör du en:

dotnet ef migrations add InitialCreate
dotnet ef database update

Ändrar du modellen (till exempel lägger till en egenskap) gör du en ny migration med ett nytt namn:

dotnet ef migrations add LaggTillDescription

Om dotnet ef inte hittas: kör dotnet tool install --global dotnet-ef igen och öppna terminalen på nytt.

Avancerat: relationer med Fluent API

Det mesta kan du göra direkt i klasserna. Lägger du en navigationsegenskap och ett främmande nyckelfält, förstår EF Core relationen av sig själv:

public class Order
{
    public int Id { get; set; }
    public int ProductId { get; set; }
    public Product Product { get; set; } = null!;
}

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public decimal Price { get; set; }
    public List<Order> Orders { get; set; } = new();
}

För specialfall använder du Fluent API i OnModelCreating. Där kan du styra saker som klasserna inte visar: vad som händer vid borttagning, längdgränser och index.

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Order>()
        .HasOne(o => o.Product)
        .WithMany(p => p.Orders)
        .HasForeignKey(o => o.ProductId)
        .OnDelete(DeleteBehavior.Restrict);

    modelBuilder.Entity<Product>()
        .Property(p => p.Name)
        .HasMaxLength(100)
        .IsRequired();
}

DeleteBehavior.Restrict hindrar att en produkt tas bort så länge det finns ordrar som pekar på den. Utan den inställningen kan borttagning kaskadera och ta bort ordrar med.

Seeder: startdata

En seeder fyller databasen med startdata, men bara om den är tom. Då kan du köra programmet hur många gånger du vill utan att få dubbletter:

public static class DbSeeder
{
    public static void Seed(WebshopContext db)
    {
        if (db.Products.Any())
        {
            return;
        }

        db.Products.AddRange(
            new Product { Name = "Kaffe", Price = 49m },
            new Product { Name = "Te", Price = 35m });
        db.SaveChanges();
    }
}

Anropa den efter migrationerna, till exempel i Program.cs:

using var db = new WebshopContext();
db.Database.Migrate();
DbSeeder.Seed(db);

EF Core har också HasData i OnModelCreating. Då blir startdatan en del av migrationen, och varje ändring av datan kräver en ny migration. Varje rad måste ha ett fast Id. Dokumentationen kallar det nu "model managed data". För allmän seeding rekommenderas UseSeeding och UseAsyncSeeding i DbContextOptionsBuilder.

Koppla på från IDE

Ibland vill du se tabellerna direkt. Använd samma värden som i din connection string.

Visual Studio

Visa → SQL Server Object Explorer. Högerklicka på SQL Server → Add SQL Server. Ange (localdb)\MSSQLLocalDB för LocalDB, eller localhost,1433 för Docker.

Rider

View → Tool Windows → Database. Klicka på + → Data Source → SQL Server eller MySQL. Fyll i host, port, användare och lösenord.

VS Code

Installera tilläggen SQL Server (mssql) av Microsoft och MySQL av cweijan. Lägg till en anslutning med host, port, användare och lösenord.

Tips och tricks
  • Använd FirstOrDefault när raden kanske inte finns. First kastar ett undantag om ingen rad hittas.
  • Läsning som inte ska ändras: lägg till .AsNoTracking(). Det går snabbare.
  • Se SQL:en: db.Products.Where(p => p.Price < 100).ToQueryString() visar SQL-frågan utan att köra den.
  • Undvik Find i en loop: varje anrop kan gå till databasen. Hämta en lista en gång.
  • Glöm inte SaveChanges(). Det är den vanligaste orsaken till att ingenting sparas.
  • Lösenord i git: lägg dem i user secrets eller miljövariabler, aldrig i appsettings.json.
  • Connection string fungerar inte: kontrollera att containern kör (docker ps) och att porten stämmer.

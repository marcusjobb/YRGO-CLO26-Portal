ADO.NET med SQLite

Fördjupad OOP i C# · Kurs 3 · CLO26 · YRGO

Skapa projektet

ADO.NET är det lägsta lagret. Du skriver SQL själv och talar med databasen direkt, utan EF Core som mellanled. Det är bra att kunna innan du använder EF, eftersom EF gör samma saker bakom kulisserna.

dotnet new console -n AdoLathund
cd AdoLathund

SQLite behöver ingen server. Paketet Microsoft.Data.Sqlite innehåller allt som behövs:

dotnet add package Microsoft.Data.Sqlite
Connection string

En connection string för SQLite är bara en sökväg till filen. Den hamnar i appsettings.json, precis som i EF-lathunden. SQLite har inget lösenord, så det finns inget hemligt att gömma.

{
  "ConnectionStrings": {
    "Sqlite": "Data Source=webshop.db"
  }
}

Sätt Copy to Output Directory på appsettings.json till Copy if newer. Läs strängen i koden:

dotnet add package Microsoft.Extensions.Configuration.Json
var config = new ConfigurationBuilder()
    .AddJsonFile("appsettings.json")
    .Build();

var connectionString = config.GetConnectionString("Sqlite");

Filen webshop.db skapas automatiskt första gången du öppnar anslutningen.

Skapa tabellen

I ADO.NET skriver du SQL själv. Den här koden skapar tabellen om den inte finns. Kör den en gång när programmet startar:

using var connection = new SqliteConnection(connectionString);
connection.Open();

using var command = connection.CreateCommand();
command.CommandText = @"
    CREATE TABLE IF NOT EXISTS Products (
        Id    INTEGER PRIMARY KEY AUTOINCREMENT,
        Name  TEXT    NOT NULL,
        Price REAL    NOT NULL
    );";
command.ExecuteNonQuery();

Lägg märke till ExecuteNonQuery(). Den används för kommandon som inte returnerar rader: CREATE, INSERT, UPDATE och DELETE.

CRUD med ADO.NET

Mönstret är alltid detsamma: öppna anslutningen, skapa ett SqliteCommand med SQL-texten, kör det och läs resultatet.

Create

Lägg till en rad. ExecuteNonQuery() returnerar hur många rader som påverkades.

using var connection = new SqliteConnection(connectionString);
connection.Open();

using var command = connection.CreateCommand();
command.CommandText = "INSERT INTO Products (Name, Price) VALUES ('Kaffe', 49)";
int antal = command.ExecuteNonQuery();

Read

Läs rader med ExecuteReader(). Read() går till nästa rad och returnerar false när det inte finns fler.

using var connection = new SqliteConnection(connectionString);
connection.Open();

using var command = connection.CreateCommand();
command.CommandText = "SELECT Id, Name, Price FROM Products";

using var reader = command.ExecuteReader();
while (reader.Read())
{
    Console.WriteLine($"{reader.GetInt32(0)} {reader.GetString(1)} {reader.GetDouble(2)}");
}

Update

Ändra en rad. Kontrollera antalet påverkade rader, så att du vet att något faktiskt ändrades.

using var connection = new SqliteConnection(connectionString);
connection.Open();

using var command = connection.CreateCommand();
command.CommandText = "UPDATE Products SET Price = 39 WHERE Name = 'Kaffe'";
int antal = command.ExecuteNonQuery();

Delete

Ta bort en rad.

using var connection = new SqliteConnection(connectionString);
connection.Open();

using var command = connection.CreateCommand();
command.CommandText = "DELETE FROM Products WHERE Name = 'Kaffe'";
command.ExecuteNonQuery();

Exemplen ovan bygger SQL-texten direkt i strängen. Det är bara ok för att se hur det fungerar. I riktig kod ska du använda parametrar, se nästa avsnitt.

Parametrar

Om du bygger SQL med strängsammanfogning kan användaren skriva in SQL i ett fält och ta över din fråga. Det kallas SQL-injektion. Parametrar löser det: värdet skickas separat och tolkas aldrig som SQL.

using var connection = new SqliteConnection(connectionString);
connection.Open();

using var command = connection.CreateCommand();
command.CommandText = "INSERT INTO Products (Name, Price) VALUES ($name, $price)";
command.Parameters.AddWithValue("$name", "Kaffe");
command.Parameters.AddWithValue("$price", 49);
command.ExecuteNonQuery();

Sök med parameter, till exempel när användaren skriver in ett namn:

command.CommandText = "SELECT Id, Name, Price FROM Products WHERE Name = $name";
command.Parameters.AddWithValue("$name", inmatatNamn);

Börja alltid med $ i SQLite. Parametern måste finnas i kommandot, annars ger SQLite ett fel.

Transaktioner

En transaktion gör flera ändringar som en enda operation. Antingen lyckas alla, eller så ångras alla. Det är användbart när en order ska skapas och lagersaldot ska minskas samtidigt.

using var connection = new SqliteConnection(connectionString);
connection.Open();

using var transaction = connection.BeginTransaction();
try
{
    using var command = connection.CreateCommand();
    command.Transaction = transaction;

    command.CommandText = "UPDATE Products SET Price = Price - 5 WHERE Name = 'Kaffe'";
    command.ExecuteNonQuery();

    command.CommandText = "INSERT INTO Orders (ProductName) VALUES ('Kaffe')";
    command.ExecuteNonQuery();

    transaction.Commit();
}
catch (SqliteException ex)
{
    // Om något steg misslyckas ångras allt som gjorts i transaktionen
    transaction.Rollback();
    Console.WriteLine($"Ändringen ångrades: {ex.Message}");
}

Varje command som ingår i transaktionen måste få Transaction satt till den.

Seeder: startdata

Kontrollera först om tabellen är tom. Skriv startdatan i en transaktion, så blir det antingen alla rader eller ingen:

using var connection = new SqliteConnection(connectionString);
connection.Open();

using var check = connection.CreateCommand();
check.CommandText = "SELECT COUNT(*) FROM Products";
int antal = Convert.ToInt32(check.ExecuteScalar());

if (antal == 0)
{
    using var transaction = connection.BeginTransaction();
    using var insert = connection.CreateCommand();
    insert.Transaction = transaction;
    insert.CommandText = "INSERT INTO Products (Name, Price) VALUES ($name, $price)";

    insert.Parameters.AddWithValue("$name", "Kaffe");
    insert.Parameters.AddWithValue("$price", 49);
    insert.ExecuteNonQuery();

    insert.Parameters.Clear();
    insert.Parameters.AddWithValue("$name", "Te");
    insert.Parameters.AddWithValue("$price", 35);
    insert.ExecuteNonQuery();

    transaction.Commit();
}

Samma mönster som i de andra lathundarna: kontrollera först, skriv sedan. Här syns transaktionen tydligast, eftersom det är du som skriver SQL.

Tips och tricks
  • Använd alltid parametrar. Strängsammanfogning i SQL är den vanligaste säkerhetsbristen i enkla program.
  • Glöm inte using. Om anslutningen inte stängs kan filen vara låst för andra program.
  • ExecuteScalar() returnerar ett enda värde, till exempel SELECT COUNT(*).
  • Kontrollera reader.Read(). Den returnerar false när det inte finns fler rader, inte när något gått fel.
  • Kom ihåg att SQLite är en fil. Radera webshop.db om du vill börja om från början.
  • Ta hand om felen. Där något kan gå fel, lägg till // Tänk på att lägga till Try Catch.
